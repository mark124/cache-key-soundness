\begin{abstract}
% DRAFT -- facts are final once results/ is final; the sentences are Mark's to rewrite.
A GitHub Actions workflow that caches a built Python environment (a
virtualenv, \texttt{.tox}, a Poetry environment) and skips installation on a
cache hit is running an incremental build. Its cache key is the only
declaration of what that environment depends on. Build-systems research has
long treated an incomplete dependency declaration as a correctness bug; CI
caching research has studied cache adoption and speed. We study where the two
meet. We state a soundness condition for cache keys of built environments,
measure it on a stratified sample of \ck{h.repos_sampled} Python repositories,
and test its consequences in a controlled experiment on GitHub-hosted runners.
Of \ck{h.built_env_steps} cache steps that store a built environment,
\ck{h.unsound_steps} (\ck{h.unsound_pct_of_built}\%) use a key that omits the
exact interpreter, and \ck{h.unsound_with_skip} of those also skip
installation on a hit. % RESULTS SENTENCE FOR THE EXPERIMENT GOES HERE
We release a linter that flags these keys. Code, data and every number in this
paper: \repourl.
\end{abstract}

\paragraph{What a virtual environment depends on.}
% - pyvenv.cfg `home =` records the base interpreter directory
% - bin/python is a symlink to that interpreter (POSIX default)

%   and each runner image carries one patch per minor version; images are updated weekly

\section{A Soundness Condition for Cache Keys}
% Definition: a cache step is SOUND for a cached path P if the key (together with the
% path list, which actions/cache folds into the cache version) determines every input
% that P's contents depend on.
% For built Python environments, the inputs are: exact interpreter (version and
% location), the dependency specification (lock file), OS and architecture.
% Operationalisation used by the classifier (Table~2 verdicts):
%   sound / minor_only / no_interpreter / version_file / not_applicable
% Two refinements: a matrix or setup-python input pinned to full patch versions is
% exact; a key computed in an earlier run step is judged by the text of that step.
% Separate hazard: a sound key with a restore-keys prefix that drops the interpreter.
